# Mainframe EBCDIC Copybook Parser

## Difficulty Explanation

This task requires parsing a mainframe EBCDIC-encoded sequential file using a COBOL copybook that defines the record layout. The difficulty stems from three layered traps that only mainframe experience reveals: (1) REDEFINES is an overlay — the same bytes at offset 44 must be interpreted as either DEBIT or CREDIT fields depending on the TRAN-TYPE discriminator parsed first; (2) COMP-3 packed decimal fields have implied decimal scaling (the "V" in PIC S9(n)V99) requiring division by 100, which is not stored in the data; (3) variable-length narrative fields are terminated by LOW-VALUE (0x00), not fixed-width despite PIC X(n) in the copybook. An expert knows to parse TRAN-TYPE before choosing the REDEFINES overlay, to unpack COMP-3 nibble-by-nibble with sign handling, and to scan for 0x00 terminators. The task uses synthetic data generated from a fixed seed (42) with 1,000 records covering both debit and credit types.

## Solution Explanation

The solution reads the 149-byte EBCDIC records sequentially, decodes fixed-width fields using Python's cp037 codec, then branches on TRAN-TYPE. For DEBIT records: unpacks 5-byte COMP-3 at offset 44 (9 digits → divide by 100), 4-byte COMP-3 at offset 49 (7 digits → divide by 100), reads narrative from offset 53 until 0x00. For CREDIT records: unpacks 6-byte COMP-3 at offset 44 (10 digits → divide by 100), reads 20-byte reference at offset 50, reads narrative from offset 70 until 0x00. Outputs JSONL with reformatted dates/times, trimmed strings, and proper decimal values.

## Verification Explanation

The verifier loads the agent's `/app/parsed.jsonl` and the ground truth `/tests/expected.jsonl` (generated by the reference parser from the same seed). It compares all 1,000 records field-by-field with exact matching: tran_seq, tran_date (YYYY-MM-DD), tran_time (HH:MM:SS), tran_type, acct_num, currency, amount (float), fee (float), narrative, and ref_number (string or null). No tolerance ranges — exact match required. The test suite validates record count, field presence, and exact values for every field.

## Relevant Experience

This task mirrors real mainframe modernization work where COBOL copybooks define EBCDIC data layouts with REDEFINES, COMP-3 packed decimals, and variable-length fields. A data engineer with 3+ years in mainframe migration (banking, insurance, government systems) would have parsed such files. The REDEFINES overlay trap and implicit COMP-3 scaling are classic pitfalls that only experience reveals — novices often treat REDEFINES as a union, miss the V-scaling, or assume fixed-width narratives.
